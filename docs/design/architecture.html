WoW: Forever addon · Architecture draft

BFF — Best Friends in Forever

A shared friends panel for a group that doesn't always play at the same time. It works across guilds and alts, with no server.

01 Core ideas

✍️

Each player writes only their own data

Clients pass friends' data along but never edit it. A higher seq wins, so there are no conflicts and no clock problems.

🕊️

Gossip sync

Any two clients online at the same time swap everything they know. A plays Monday, C plays Tuesday, and B carries the news in between.

✨

Events come from comparing data

"Kari dinged 24" is never sent as a message. Each client works it out by comparing old and new data.

02 Module layers

UI
Panel · login summary popup · overlap finder. Only reads from the Store and re-renders when it changes.
Feed
Compares old and new data to produce ding, zone, death and alt events, plus the "while you were away" summary.
Store
Owns the saved data. upsertChar(), merge(), change callbacks. The only module that writes to the database.
Snapshot
Reads your own character's state from game events.
Sync
The protocol: HELLO, WANT, DATA, PING, with jitter.
Transport
One send(msg, scope) call over Channel · Guild · Whisper · Battle.net.

03 Data model

The saved data is account-wide, so every character on one account belongs to the same person automatically. Alts link with no setup.

BFF_DB = {
  me    = { pid = "k3f9a2", name = "Stian" },  -- random id + display name
  group = "broskis",                         -- namespace; ignore other groups

  people = {
    k3f9a2 = {
      name  = "Stian",
      main  = "Thrallbane-Realm",
      chars = {
        ["Thrallbane-Realm"] = {
          seq   = 412,          -- owner's counter; higher wins
          t     = 1793481234,   -- GetServerTime() at last write
          class = "WARRIOR", faction = "Horde",
          level = 24, xp = 8120, xpMax = 13600,
          zone  = "Stranglethorn Vale",
          deaths = 7, played = 191233,
        },
      },
    },
    -- …friends' records, gossiped in
  },

  seen = { … },  -- copy from last logout, used for "while you were away"
}
Merge rule: a received record replaces your copy only if its seq is higher. People who play on several accounts can link them with a short code that reuses the same pid.

04 Sync protocol

HELLO

Digest: {charKey → seq} for every character you know about. A few hundred bytes.

On login or reload, and when a new peer appears
WANT

List of character keys where the other side has newer data than you.

After reading a digest
DATA

Full records the other side is missing or has old versions of.

In reply to a digest or WANT, or when your own data changes
PING

Your character key and seq. Presence heartbeat and cheap change check.

Every ~5 minutes while online

Example: C logs in after missing A

Batching your own updates

Level up → immediately Zone change → ~10 s XP → at most every 60 s Online → PING within 6 min or game friend list

05 Transport

BackendReachesNotes
Custom channelSame realm group and factionMain bus. Auto-joined and hidden from chat. Doesn't need a guild.
GuildGuild membersBonus route when some of you share a guild
WhisperA specific known online characterDirect replies

Duplicates arriving over more than one route are harmless, because the merge ignores records with an equal or lower seq.

07 Risks to check in the client

HIGH

Channel restrictions

Modern WoW requires a real key press or click for some channel and chat calls. Joining automatically, or sending addon messages over custom channels, might be blocked. That's why Transport is swappable.

MED

Forever API gaps

There's no official API reference. Check that the XP, level and zone events fire as expected.

MED

Battle.net messages

Only work between Battle.net friends, and need the receiver's account linked to a character.

LOW

Message limits

Each addon message is capped at 255 bytes and sending is throttled. Fine for a small group with AceComm. Keep full syncs rare.
