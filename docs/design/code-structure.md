# Code structure and testing

Answers [How is the code split into modules and tested?](https://github.com/Shtian/bff-wow/issues/9). Builds on the sync resolution in #8 and `docs/adr/0001-owner-written-records-gossiped-by-server-time.md`. Domain vocabulary from `CONTEXT.md`; architecture vocabulary (module, interface, seam, adapter, depth) as in the `codebase-design` skill.

## The idea in one line

Almost all behaviour lives in one deep, pure-Lua module, **Core**, behind a small interface. The WoW-facing code is thin. Offline tests and `/bff sim` drive real Cores against each other through a fake link.

## Modules

| Module | Pure? | Owns |
|---|---|---|
| **Core** (`Core/`) | yes | Everything BFF knows and decides: Member records, sync, Feed, panel rows, saved-data layout. Details below. |
| **Snapshot** (`Game/Snapshot.lua`) | no | Reads level, XP, zone, class, gold, professions (through `Professions.read`) and GUID, counts deaths (kept per Character in `BFF_CharacterDB`), and calls `core:updateOwn(character)`. `Snapshot.locate()` reads where the Character stands, for Core's `locate`. `Snapshot.encounter(...)` turns `ENCOUNTER_END`'s payload into `encounterEnded()`'s, with the instance type and the group, secret values as nil. `Snapshot.catch()` reads the loot window through `Catches.read` on `LOOT_READY`, for `caught()`. |
| **Bags** (`Game/Bags.lua`) | no | Offers a bag item as a Spare: the item on the cursor (the Spares tab's drop slot) or the first bag item matching a link (`/bff spares add`). Passes its item GUID and binding to `core:postSpare`, which refuses an item that can't be traded. Also tells Core where a posted item is now (`findItem`), for `core:bagsUpdated` on `BAG_UPDATE_DELAYED`. |
| **Channel link** (`Game/ChannelLink.lua`) | no | The production link adapter: joins and hides the Crew channel (including filtering its system notices out of chat), learns who else is in it from its member list and join and leave notices, sends each message as an AceComm addon whisper (with ChatThrottleLib) to every other Character in the channel, decides when the link is up or down, and reports Members leaving the channel. Its half of the sync trace (`setTrace(fn)`): each whisper sent per Character with its bytes and chunks, each whisper received with its sender and bytes, each chunk's result, the link going up or down and why, chat restriction changes, "No player named …" and "Player is offline." notices, the peers list changing and why, and stranger whispers held or dropped. On Forever addon messages sent to a custom channel never arrive, so the channel only carries presence. See `docs/research/channel-spike.md`. |
| **UI** (`UI/Skin.lua`, `UI/CampSheet.lua`, `UI/CampScene.lua`, `UI/Panel.lua`, `UI/TogetherTab.lua`, `UI/CatchesTab.lua`, `UI/GoalsTab.lua`, `UI/Minimap.lua`, `UI/MapPins.lua`, `UI/Away.lua`, `UI/ToastQueue.lua`, `UI/Toasts.lua`, `UI/Settings.lua`) | no | Renders Core's rows and summaries and sends user commands to Core. Shows no state it worked out itself. Skin is the shared flat look (colours, fonts, window, buttons, Feed icons) for the panel, the popup, toasts and map pins. CampScene draws Core's `camp()` as pixel art from the sheet CampSheet describes (generated by `scripts/camp-art.mjs`), for the panel's band, the popup and the small figures on Roster rows and toasts (`docs/design/camp.md`). ToastQueue is pure and tested offline (`docs/design/toasts.md`). |
| **App** (`BFF.lua`) | no | Wiring only: creates Core, routes WoW events (`UI_SCALE_CHANGED` and `DISPLAY_SIZE_CHANGED` redraw the panel, for the Camp's art pixel), runs a 1 s `C_Timer` ticker that calls `core:tick()`, and handles slash commands. `/bff debug sync` turns the sync trace on or off for the session: one `trace(line)` function, given to Core and the channel link, prints each line with the time of day and `GetTime()`. In a dev checkout, once the `/bffdev` console has been opened, the lines go to the console's log instead of chat (`ns.traceSink`), and its **Sync trace** box turns the trace on or off too. |

The first draft's Zones module is dropped from v1, because only the overlap finder needed it. The overlap finder (the Together tab) works from levels and a dungeon table instead.

## Core

### Interface

Core is created with:

- `db`: the whole `BFF_DB` table. Core owns its layout, defaults and migrations, settings included.
- `now()` and `random()`: the clock (`GetServerTime` in game) and randomness, so tests are deterministic.
- `link`: the outgoing half of the link port (`send(string, to)`).
- `listener`: receives Core's events.
- `initialLogin`: `isInitialLogin` from `PLAYER_ENTERING_WORLD`, so Core can tell a login from a reload (see `docs/design/feed.md`).
- `maxLevel`: from `GetMaxLevelForPlayerExpansion()`, for max level Feed entries.
- `utcOffset`: how many seconds local time is ahead of server time, so `feed()` starts each day at local midnight and `playTimes()` shows local hours (default 0).
- `locate()` (optional): where the Character being played stands, as `Snapshot.locate()` reads it: `{ mapId, x, y }` in the open world, `{ instance }` inside an instance, or nil when it can't be read. Core calls it just before its own DATA goes out (a zone change, a ding, the heartbeat), so moving alone never sends anything or changes the record. The Ledger rounds the position to 0.1%, keeps the last open-world spot inside an instance, and keeps the last known spot on nil.
- `itemLink(itemString)` (optional): the game's link for an item string, as `Snapshot.itemLink` reads it, or nil while the item isn't cached. Spare texts say "an item" until then (`docs/design/spares.md`).
- `itemLook(itemId)` (optional): how the game shows an item, as `Skin.itemLook` reads it: `{ text, icon, edge }`, the name in its quality colour, the icon and the quality colour, each nil while it isn't cached. Rare finds use the English name until then (`docs/design/feed.md`).
- `findItem(itemGuid)` (optional): where a posted item is now, as `Bags.findItem` reads it: whether it's in the bags or bank (nil if the game can't say), and whether it's equipped.
- `finalBosses` (optional): encounter ID to instance name, the kills that are Clears. Defaults to `Core.FINAL_BOSSES`, from the dungeon table's `finals`; tests and the dev sim pass their own while Forever's IDs aren't known.
- `gossip` (optional): the Gossip module to use. Only FakeNet passes one, for a client that syncs like an older BFF (`tests/fixtures/legacy_gossip.lua`).

Inputs:

- `updateOwn(character)`: the current state of the Character being played, from Snapshot.
- `tick()`: once a second. Core decides what is due (reply delays, debounced sends, heartbeat, online timeouts, pruning), and counts the second towards Play times.
- `received(string)`, `up()`, `down()`, `gone(name)` and `sendFailed(name)`: the incoming half of the link port.
- `bagsUpdated()`: on each `BAG_UPDATE_DELAYED`, never before the first of a session. Core checks where each own Spare's item is (ADR 0004).
- `caught(loot)`: on `LOOT_READY` (a loot window's catch once), from `Snapshot.catch`: `{ items, zone, subzone, mapId }`, or nil when the loot isn't from fishing. Each item goes into the own record as a Catch, shared with the next send, or now for a rare find, which makes a Feed entry. Types caught can reach a Crew goal step (`docs/design/catches.md`).
- `encounterEnded(encounter)`: on `ENCOUNTER_END`, from `Snapshot.encounter`: `{ encounterId, success, instanceType, party }`. A known final boss killed in a party or raid instance, in a Crew, is a Clear in the own record (ADR 0005); returns the instance's name, or nil and why not (`docs/design/trophies.md`).
- Commands: start, join and leave a Crew, change the display name, Set as Main, Remove and re-add a Member, Pause sharing, and settings (see `docs/design/joining-a-crew.md`). Spares: post (with the item's GUID, kept locally, and its binding: an item that can't be traded is refused), withdraw and Give one, and make and withdraw a Claim (`docs/design/spares.md`).

Outputs:

- `link.send(string)`: best-effort (see the link port below).
- Listener events:
  - `changed`: re-read whatever you show (`rows()`, `feed()` and the rest). Also fires when a Member passes the 12-minute online timeout, even though no record changed. Settings don't fire it.
  - `settingChanged(key, value)`: a setting really changed (setting a value it already has fires nothing). App passes it to Panel, Minimap, Toasts and Settings, and each ignores keys it doesn't use: Toasts clears its queue when `toasts` turns off, Minimap shows or hides the button on `minimap`, Panel redraws on `paused` (its footer status) and `camp`, and moves, resizes and redraws on `panelPlace`, and the Settings page updates that key's control.
  - `feedEntry(entry, outlets)`: a Live event from the Feed. While the Camp is on, an entry about a Member the Roster shows has `figure`, that Member's shown class, for the toast. Core decides where it goes: `outlets` is `{ chat, toast }`, from the chat-line and toast settings, and App prints `entry.text` and shows a toast exactly as told, reading neither setting. With both off it isn't fired, and the entry stays unseen for While you were away.
  - `reaction(news, outlets)`: a live Reaction to one of your entries, fired and shown the same way as `feedEntry`. Toasts for the same entry merge (see `docs/design/reactions.md`).
  - `spare(news, outlets)`: a live Spare notice (a Claim now winning yours, or one Given to you), fired and shown the same way as `feedEntry` (see `docs/design/spares.md`).
  - `spareGone(gone)`: at the first bag check after a real login, a Spare whose item is gone was withdrawn (`action` "withdrawn": App says so in chat) or has a Claim (`action` "ask", with its `winner`: App asks whether to Give or withdraw it).
  - `awaySummary(summary)`: While you were away has settled after an initial login. Fired only when the popup setting is on and it isn't empty. App shows it once out of combat. It comes worded, so the popup only lays it out: the scoreboard's `intro` ("2 things happened while you were away."), the `maxLevel` its level bars run to, each Character's `label` ("Alt Jaina", the Main's name, or nil for a Main named like the Member) and `gained` ("+2" or "new"), each Member's `tags` (`{ text, highlight }` for joined and left), a `highlight` flag on each profession line, and `catches`: the line of new types others caught, then the rare finds missed. With the Camp on, `camp` is the Camp at `Core.CAMP_LAYOUT.awayColumns` without the tent, each actor with `gained` (its Main's, as the scoreboard words it; nil with nothing gained) and `highlight` (max level), and `intro` reads "The fire kept burning. 7 things happened in camp."
  - `notice(kind)`: one-off messages ("BFF is out of date", "you left the Crew").
  - `crewChanged`: the Crew was joined or left. App tells the channel link to join or leave the channel from `crew()`.
- Settings: Core holds one ordered list of the local settings (`docs/design/settings-and-release.md`). `setting(key)` reads one and `setSetting(key, value)` sets it; `settings()` is the Settings page's ready-to-render read, a section per `{ title, settings }`, each setting `{ key, kind, label, value }`. The named methods (`isPaused()`/`setPaused()`, `isMinimapShown()`/`setMinimapShown()`, `isChatLinesOn()`/`setChatLines()`, `isAwayPopupOn()`/`setAwayPopup()`, `isToastsOn()`/`setToasts()`, `toastSound()`/`setToastSound()` and `toastPosition()`/`setToastPosition()`) are one-line wrappers over these. `setPanelPlace(width, height, left, top)` and `resetPanelPlace()` save the panel's size and position (clamped to its limits, `Core.PANEL_MIN_*`/`PANEL_MAX_*`), and `panelPlace(screenWidth, screenHeight)` says where it opens on this screen: shrunk to fit, moved onto it, and with nil `left`/`top` for centred. `minimapIcon()` is the saved table LibDBIcon keeps the button's position and the minimap setting's hidden flag in.
- Reads: `crew()` (code, channel name and password, a `leaving` flag while a leave is pending, `alone` while no other Member is known, and `status`: the Roster footer's finished line, the first that applies of leaving, appearing offline and waiting for your Crew, else nil; or nil outside a Crew) and `displayName()`.
- Ready-to-render reads for UI: `rows()` (each row and Character with its finished `lastSeenText`: "5m ago", "online" on a row while online, nil on your own row; each row's `status`, the right-hand text, "by the fire" and "asleep · 5m ago" with the Camp on, else its `lastSeenText`; and each other Member's `section`, "BY THE FIRE" or "ASLEEP IN CAMP" sorted Online first with the Camp on, else "CREW"), `summary()` (the counts, Spares for you, and `header`: "1 of 4 online", or "2 of 5 by the fire" with the Camp on), `camp(columns)` (the Camp at a band `columns` art pixels wide, in `Core.CAMP_LAYOUT`'s geometry, or nil while the `camp` setting is off: actors, graves, tent and more, `docs/design/camp.md`), `feed()` (the Feed tab's entries grouped by day, each day with its finished `title` ("TODAY", "YESTERDAY", "MONDAY 02 NOVEMBER"), each entry with `highlight` (the news), `new` (see the Feed visit below) and its reactors in order, yours named "You" and marked `you`, plus the unseen count), `goals()` (the Goals tab's row per Crew goal track, `docs/design/goals.md`), `trophies()` (every Crew goal rung reached and every instance the Crew has cleared as a trophy, for the Goals tab's latest win, shelf and cabinet, each with its finished `date`, `quality` and `fresh`, a clear's with its `party` by name; the cabinet's `dungeons` and `raids` grids, a slot per instance; `openGoals()` and `leaveGoals()` make the Goals visit its since-last-opened count holds through), `playTimes(memberId?)` (the When tab's grid for the Crew or one Member, with its finished `title`, `intro` and `note`, `docs/design/play-times.md`), `mapPins()` (a world map pin per other Member the Roster shows, at their shown Character's last-seen spot), `spares()` (the Spares tab's rows, From the Crew and Yours, each with its finished `info` line, its buttons (`primary` Claim or Give with `enabled`, `secondary` Withdraw, nil when not shown) and `highlight` and `dimmed` flags, plus `claimFor`: your Characters for the Claim menu, Main first, `{ guid, label }`), `professions(order?, sortBy?)` (the Professions tab's grid: a row per Member and a cell per profession, their best Character's skill, `docs/design/professions.md`), `catches()` (the Crew's Catches: per type, the earliest catch across the Crew and the Crew's count, the types caught out of those counted, and the unlisted catches, `docs/design/catches.md`), `catchesTab(group?, show?)` (the Catches tab: that as a field guide, grouped by where to fish or type and filtered by Show, every tile, tooltip and empty state worded, and the Group and Show menus, `docs/design/catches.md`), `together(measure?, selected?)` (the Together tab: friends and every dungeon shown placed on the level line in `Core.TOGETHER_LAYOUT`'s geometry, what's shared with the Members picked, and the Show menu, whose choices are the `together*` settings, `docs/design/together.md`; the dungeon table is `Core.DUNGEONS`, and `Core.selectTogether(selected, memberIds, add)` gives the pick after a click), `spareItems()` (the item GUIDs of the open Spares the Character being played posted), and `unseen()` (the unseen count alone, for the minimap tooltip and the panel's sidebar while the Feed isn't shown). UI never sees a Member record.
- The Feed visit: `openFeed()` is called on every draw of the Feed tab, before `feed()` is read. It starts a visit if none is open, and every entry (or Reaction to your own) unseen at that moment is seen, and **New** in `feed()` until `leaveFeed()`, called on leaving the tab or hiding the panel. Core marks entries seen itself when it fires `feedEntry` (or `reaction`, `spare`) or `awaySummary`, so an entry a Live event already showed is never New.
- `react(key)` reacts to someone else's Feed entry, with a key from `feed()` or the summary.
- The sync trace: `setTrace(fn)` makes Core call `fn(line)` with a line of text (no timestamp) for each message it sends (type, each record's name, id and version or a DIGEST's count and versions, and its size in bytes) and receives (sender, type, the decode result `ok`, `invalid` or `newer`, a DIGEST's versions, and per DATA record whether it was merged and how late it is: now minus its version). `setTrace(nil)` turns it off; Core then builds no lines. Off for every new Core. Tested in `trace_spec`.

### Inside Core

These are internal seams: separate files for locality, tested only through Core's interface, with nothing swappable behind them. The one exception is the `gossip` dep, so mixed-version tests can run a client with an older BFF's Gossip.

- **Ledger** (`Core/Ledger.lua`): what we know. Holds the own record and copies of everyone else's, the merge rule (a higher version wins), the Remove list, the "left" flag, last-heard times, and 180-day pruning. It stores and writes records (versions, the bump, what Gossip sends) and prunes on every own write, but never reads the Spares layout: the Spares module writes its part of the own record through `changeOwn`, and prunes it through the pruner it hands over with `pruneWith` at setup, since only Spares knows which Spares and Claims have ended. Removing a Member deletes their record and drops future copies. Re-adding takes them off the list and sends a DIGEST, and peers reply with DATA.
- **Gossip** (`Core/Gossip.lua`): when to talk. Owns the DIGEST and DATA rules, 1–4 s reply delays and suppression, send timing (immediate, 10 s zone debounce, "later" changes such as XP within 60 s, 5-minute heartbeat), the DIGESTs that recover lost messages (see Sync below), the "record changed" and "reply owed" flags, and Pause.
- **Feed** (`Core/Feed.lua`): turns a before/after record pair from Ledger into Feed entries, including skipped versions such as 22 → 24. For others' "gave" entries it asks Spares (`Spares.newlyGiven`) what was newly Given between the two; your own come from Spares when you Give. Feed owns how a "gave" entry looks. Also owns the capped log, seen flags, and when While you were away is ready. See `docs/design/feed.md`.
- **Reactions** (`Core/Reactions.lua`): the pure parts of Reactions: which Reaction each entry kind has, the key a Reaction points at an entry by, how keys are stored in a record and pruned, and the wording the owner sees. Feed attaches Reactions to its entries. See `docs/design/reactions.md`.
- **Spares** (`Core/Spares.lua`, with `Core/SpareRules.lua`): the whole Spare lifecycle, and the only Spare interface Core uses. Owns posting, withdrawing and Giving, making and withdrawing Claims, expiry, who wins (ADR 0003), the item-gone state and bag check (ADR 0004), the item GUIDs of own Spares (local only), the Spares tab's rows, the Roster's count and the notices with their seen flags. Core's Spares commands only delegate to it. Behind it, SpareRules is a private file of stateless helpers: the trimmed item string, whether an item can be traded, how Spares and Claims are stored in records, the caps and pruning, the item-gone decision and the winner's tie-break. See `docs/design/spares.md`.
- **Text** (`Core/Text.lua`): pure wording helpers the ready-to-render reads share: how long ago ("5m", "3h", "2d"), and a Feed day's title and a short date in local time, worked out from the server time and `utcOffset` since Core has no `date()`. Tested directly (`text_spec`).
- **Settle** (`Core/Settle.lua`): when sync has gone quiet after the link came up (10 s with no new DATA, at most 30 s). Feed uses it for While you were away, Goals for its silent baseline.
- **Goals** (`Core/Goals.lua`): the built-in Crew goal tracks and their rungs, progress worked out from Ledger's records, the reached rungs (which were quiet), the Crew's clears, the silent baseline, the Goals tab's rows and its trophies, and when the tab was last opened. See `docs/design/goals.md` and `docs/design/trophies.md`.
- **Clears** (`Core/Clears.lua`): the pure parts of Clears: which kill clears which instance (`Clears.FINAL_BOSSES`, from the dungeon table), how clears are kept in a record, and the Crew's clears over a list of records. Stateless, tested through Core. See `docs/design/trophies.md`.
- **PlayTimes** (`Core/PlayTimes.lua`): counts the own Member's seconds played per UTC hour of the week for the last 4 weeks, makes the summary their record shares, ages summaries by the viewer's clock and shifts them into local time. See `docs/design/play-times.md`.
- **Professions** (`Core/Professions.lua`): the pure parts of Professions: reading them from the game through the API handed in (secret values and errors keep the last list), how a list is stored in a record and checked, ranks, the Feed news between two lists (`Professions.news`: picked up, milestones, maxed), and the Professions tab from Roster's rows (`Professions.tab`). See `docs/design/professions.md`.
- **Catches** (`Core/Catches.lua`): the pure parts of Catches: the list of types and waters (data), reading a catch from the loot window through the API handed in (`Catches.read`), how catches are kept in a record (`Catches.add`, with the unlisted cap), the Crew's catches over the records, skipping anything malformed (`Catches.collect`, `Catches.typesCaught`), and what's news in them: rare finds (`Catches.rareHeld`, `Catches.rareFinds`) and While you were away's line (`Catches.newTypesLine`). Stateless, tested through Core, with `Catches.read` tested directly. See `docs/design/catches.md`.
- **Together** (`Core/Together.lua`): the dungeon table, and the Together tab from Roster's rows: which Characters show, who can play and who fits each dungeon (Members counted once), label rows and dungeon lanes, and what's shared with the Members picked. Pure and stateless, tested through `together()`. See `docs/design/together.md`.
- **Camp** (`Core/Camp.lua`): the Camp from Roster's rows and Feed's recent entries (`Feed:since`): who's in it and in what pose, graves and flowers, sparks, placement in art pixels (`Core.CAMP_LAYOUT`), what doesn't fit, and its wording on rows, the header and the popup's intro. Pure and stateless, tested through `camp()`. See `docs/design/camp.md`.
- **Roster** (`Core/Roster.lua`): builds panel rows from Ledger. Covers Main resolution, "on alt", online (heard within 12 min, and not seen leaving the channel since), Last seen, "can play with you" (±3 levels), the 30-day hide and sorting.
- **CrewCode** (`Core/CrewCode.lua`): generates, normalises and checks Crew codes, and derives the channel name and password from them.
- **Codec** (`Core/Codec.lua`): a plain-text protocol version header, then the LibSerialize + LibDeflate body (`1|<payload>`). A newer version is detected before anything is decoded.

## The link port

This is the only real seam in v1. Its adapters are the channel link and the fake link. The retail spike (`docs/research/channel-spike.md`) showed the channel carrying addon messages, but on WoW: Forever they are accepted and never delivered, so the channel link sends over a whisper mesh: the channel says who is online, and each message is whispered to each of them.

- Core → link: `send(string, to)`: to every other Character in the channel, or with `to` (a bare Character name) only to that one. **Best-effort**: a message can be lost silently, including messages ChatThrottleLib had queued when lockdown began. The channel link sends a one-chunk message (every DIGEST) at `ALERT` priority and anything longer at `NORMAL`, so chunks of two multi-chunk messages to the same friend never interleave.
- Link → Core: `received(string)`, `up()`, `down()` and `gone(name)`. The sender's name is never passed with a message; identity travels inside the payload. Core drops messages carrying its own Member id (the fake link echoes your own messages back; whispers don't).
- `gone(name)`: a Character left the channel, i.e. logged out (a real logout leaves the channel before any goodbye could be sent, so there is none). The name is bare (`Ambiguate(sender, "none")`). Core marks the Member owning a Character of that name offline right away; the 12-minute timeout stays as the fallback. It is only a presence hint, never used to identify data.
- `sendFailed(name)`: a chunk to that Character failed (anything but a throttle, which ChatThrottleLib retries itself: a general error, a logout, lockdown, or a Trial or Veteran account, which can't send addon messages since Forever 1.60.1). Only that friend may have missed something, so the link stays up, replies owed to others stay owed, and Core sends that friend a DIGEST of their own 5 s later (at most one a minute per friend, since an account that can't send fails every time). If "No player named …" follows, or "Player is offline." within 3 s of a failed send to that one friend only (it names no one, so after failures to several it is put down to none of them), the channel link drops them from its peers and calls `gone(name)`.
- Each adapter decides what "down" means. For the channel link it is `C_ChatInfo.InChatMessagingLockdown()`, or not yet in the Crew channel, or having left it, or the channel's first member list not in yet (at most 5 s). A Character found in the channel later (the list is asked for again every minute) makes it go `down()` and straight back `up()`, so they get a fresh DIGEST. A whisper from someone not yet known to be in the channel waits for a member list that shows them, and is dropped after 10 s otherwise.
- On every `up()`, Core sends a fresh DIGEST, plus its own DATA if its record changed while the link was down. This rule covers first join, rejoin and lockdown clearing; the DIGESTs below cover messages lost while it is up.
- Lockdown and Pause never appear in the port. Lockdown is the adapter's reason for being down. Pause is Core policy. Don't gate sending on `AreOutgoingAddonChatMessagesRestricted()`, which the spike saw return true on accounts that sent fine; a Trial or Veteran account's failed sends only cost it a DIGEST a minute per friend.

## Sync: recovering lost messages

A message is lost without anyone knowing: a lost chunk loses the whole DATA, and nothing tells the sender (`docs/research/addon-message-reliability.md`). There are no ACKs (ADR 0006). Instead DIGESTs go out on their own, and a friend who missed something sees it in one and asks:

- **Confirming DIGEST:** 20–30 s after own DATA goes out, a DIGEST follows it. A friend who missed the DATA sees a newer version and replies with their own DIGEST, which makes the sender owe it. A lost ding arrives within about 40 s.
- **Every minute:** while the link is up, a DIGEST goes out 55–65 s after the last one (any DIGEST to everyone restarts the wait, the confirming one included).
- **After a failed send:** that friend gets a DIGEST of their own (`sendFailed`, above).
- **"Later" changes** (XP, gold, Play times, professions, catches) go out within 60 s instead of waiting for the heartbeat.
- **Taking turns:** a DIGEST holds 10 entries (one 255-byte message): the own record, then any ids a reply DIGEST is meant to fetch (with the version held, 0 if none, so whoever holds them replies), then the other records in turn by id, carrying on from where the last DIGEST stopped. In a Crew of more than 10 Members every record is listed within `ceil((Members − 1) / 9)` DIGESTs. One that left records out says `partial = true`, and a record it doesn't list isn't owed. Older clients ignore the flag (and owe whatever is missing, as before), and a DIGEST without it means what it always did, so mixed versions sync with no protocol bump. Every DIGEST from this version also says `turns = true`; one without it comes from an older client. Since an older client answers every DIGEST that leaves records out with DATA for all of them, the every-minute DIGEST is skipped while one was heard in the last 15 minutes and there are more than 10 records (confirming and per-friend DIGESTs still go out). In an idle Crew of 14 with two older clients, that keeps the busiest Member at 27 whispers a minute instead of 105.
- **In flight:** a record that went out to everyone (sent, or heard as DATA) in the last 2 s isn't owed to a DIGEST showing an older version: that DIGEST most likely crossed it on the way. A later DIGEST catches a real loss.
- **Traffic** (FakeNet, whispers sent a minute per Member, each chunk to each friend counted once; `BFF_TRAFFIC=1 busted tests/sync_spec.lua` prints them): a Crew of 4 idle, the busiest Member 4.5 (before this change 0.6); one Member grinding, 11.4 (2.1). A Crew of 6 idle, 7.5 (1.0); grinding, 25.0 (3.5). That is under one whisper every 2 s, against the server's allowance of about one addon message a second per prefix (which whispers outside instances may not even count) and ChatThrottleLib's 800 B/s.

## Loading pure code in game and in tests

Every file starts with `local _, ns = ...` and attaches itself to `ns`, the addon's private table. Files in `Core/` only touch `ns`, Lua builtins, the `bit` library (WoW and LuaJIT both have it) and the pure libraries (LibSerialize, LibDeflate). The test loader mimics the `.toc` with `loadfile("Core/Ledger.lua")("BFF", ns)`. A luacheck rule bans WoW globals in `Core/`.

## Tests

- **Runner:** busted under LuaJIT, linted with luacheck.
- **The interface is the test surface.** Tests create Cores and check `rows()`, the While you were away summary, Feed entries, and the recorded listener events and sent messages. They never look inside `db`, Ledger or Gossip.
- **Pure, stateless helper files may be tested directly**, table-style, as `codec_spec` does for Codec, `text_spec` for Text, `spare_rules_spec` for SpareRules, `professions_spec` for reading professions and `catches_spec` for reading the loot window. Anything with state or lifecycle is tested through Core.
- **Fake network** (`Dev/FakeNet.lua`):
  - One shared virtual clock and scheduler, so every run plays out the same way.
  - Each simulated client is a real Core with a fake link and its own `db`.
  - Per client: online or offline (link up or down), lockdown (link down while still online), Pause, reload (a new Core over the same `db`), and crash (a new Core over a copy of `db` taken at the last logout or reload).
  - Delivery is a broadcast to every client whose link is up (or, with `to`, a whisper to one), after a small delay, with optional drops (`drop`: lost, no one told) and failed sends (`fail`: the sender hears `sendFailed`) to test the best-effort contract.
  Delivery includes the sender itself, as the real channel does. A client going offline fires `gone(name)` on the others; a crash can skip it.
  - Messages go through the real Codec.
- **Scenarios** include:
  - C logs in after missing A's ding, learns it from B, and D stays quiet.
  - A crashes and its next version still wins.
  - Changes made during lockdown go out after one DIGEST when it clears.
  - A lost message is recovered at the next `up()`, and a lost ding within a minute while it stays up.
  - A failed send to one friend leaves the link up for the others and sends that friend a DIGEST of their own.
  - XP and gold reach friends within a minute.
  - In a Crew of 14, every record is listed in a DIGEST within two rounds, and records left out make no one send DATA.
  - A Member on an older BFF (`tests/fixtures/legacy_gossip.lua`) syncs both ways, in a Crew of 3 and of 13.
  - Traffic stays well under the throttle in a Crew of 4 and of 6.
  - A removed Member is never shown or relayed.
  - Someone going quiet flips to offline after 12 minutes.
  - Ten Members with three Characters each: the DIGEST fits one message.
- **WoW stand-ins** (`tests/wow_stubs.lua`): only for the channel link (`channel_link_spec`: targeted sends, priorities, failed sends and "Player is offline."). The file is loaded with the stand-ins as its globals. UI frames aren't tested offline.
- **In game:** `/bff sim` reuses FakeNet to attach a few simulated Members to your real Core, so the panel and Feed can be tested without a friend online. Their records are kept and relayed like real ones, so it only runs in a Crew where no one else is known yet. `/bff sim ding` makes one ding, `/bff sim stop` logs them out. The `.toc` lists `Dev/` inside `#@do-not-package@`, so releases don't load it. Echo mode on the channel link loops your own messages back to you.
- **GitHub Actions** (`test.yml`) on every push and PR: `leafo/gh-actions-lua` (LuaJIT) and `leafo/gh-actions-luarocks`, `luarocks install busted luacheck`, fetch libraries, then `scripts/check.sh` (`luacheck`, then `busted`), the same command you run locally.

## Libraries

| Library | Why |
|---|---|
| LibStub, CallbackHandler-1.0 | required by the rest |
| AceComm-3.0 | splits messages over 255 bytes |
| ChatThrottleLib | send limits (used by AceComm) |
| LibSerialize, LibDeflate | compact payloads; pure Lua, so tests use them too |
| LibDataBroker-1.1, LibDBIcon-1.0 | minimap button |
| HereBeDragons-2.0, HereBeDragons-Pins-2.0 | world map pins (`UI/MapPins.lua`); 2.18+ knows WoW: Forever |

Not embedded: AceDB (Core owns plain SavedVariables), AceConsole and AceEvent (a few lines with `SlashCmdList` and an event frame), and AceConfig (the native Settings API).

**Fetched, not committed**, as most addons do: libraries are declared as externals in `.pkgmeta`, which the BigWigs packager fetches at release time, and `Libs/` is in `.gitignore`. `scripts/fetch-libs.sh` checks out the same externals into `Libs/` for the dev loop (run once on the Windows PC from Git Bash, and again after a library bump) and in CI. `.pkgmeta` also leaves `tests/`, `Dev/`, `scripts/` and the bumpy files out of releases. Releases are cut with bumpy and built by `scripts/package.sh`; see `docs/design/settings-and-release.md`.
